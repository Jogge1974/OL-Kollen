USERSECRETS har skapats till projekt OL-Kollen och OLmanagerBE
Det betyder att .NET sparar hemligheterna lokalt på din dator, kopplat till just det projektet, i stället för i appsettings.json.
Om du kör dem i PowerShell händer detta:

de hamnar inte i git
de skrivs inte in i repo-filerna
de följer bara din lokala användarprofil på datorn
Så du ska byta ut platshållarna mot riktiga värden, till exempel:

dotnet user-secrets set "Eventor:WebUsername" "mitt_användarnamn" --project "C:\Workspace\OL-manager\GameServer\OLmanagerBE\OLmanagerBE\OLmanagerBE.csproj"
dotnet user-secrets set "Eventor:WebPassword" "mitt_losenord" --project "C:\Workspace\OL-manager\GameServer\OLmanagerBE\OLmanagerBE\OLmanagerBE.csproj"
dotnet user-secrets set "ConnectionStrings:SupabasePostgres" "Host=...;Port=5432;Database=postgres;Username=...;Password=...;SSL Mode=Require;Trust Server Certificate=true" --project "C:\Workspace\OL-manager\GameServer\OLmanagerBE\OLmanagerBE\OLmanagerBE.csproj"
Bra att veta:
det här fungerar främst för lokal utveckling
på en server sätter man normalt environment variables eller secrets i hostmiljön i stället
du kan se vad som sparats med:
dotnet user-secrets list --project "C:\Workspace\OL-manager\GameServer\OLmanagerBE\OLmanagerBE\OLmanagerBE.csproj"
Så kort sagt: kommandona sparar dina känsliga värden säkert lokalt så att scrapern kan logga in och skriva till Supabase utan att du lägger hemligheter i projektfilerna.
